# 돌봄 근무일지 캘린더

돌봄 근무 중 **무슨 일을 했는지, 어떤 특이사항이 있었는지**를 날짜별로 기록하고,
**해설사 근무표**(https://haeseolsa-schedule.vercel.app/)의 내 근무를 같은 캘린더에 함께 보여주는 웹페이지입니다.

- **상단에서 골라 보기**: `전체` · `돌봄` · `근무` · `일정` (+ 직접 추가한 메뉴).
  여러 개를 함께 켤 수 있고, 켜진 메뉴를 다시 누르면 꺼집니다. `전체`는 모두 다시 켭니다.
- **한 줄 일정**: 시간과 한 줄 글만 적는 가벼운 기록. 캘린더 칸에 한 줄로 나타납니다.
- **메뉴 편집**: 「병원」·「개인」처럼 한 줄 일정 메뉴를 늘리고, 모든 메뉴의 색을 바꿀 수 있습니다.
- **공휴일 표시**: 설·추석·대체공휴일·선거일까지 날짜를 빨갛게 하고 이름을 적습니다. (2025~2027년)
- **월 90시간 확인**: 월 90시간을 넘으면 추가 급여가 없으므로, 캘린더 위에 **90시간까지 남은 시간**을 크게 보여줍니다.
  넘으면 초과 시간을 빨갛게 알려주고, 일지를 쓸 때도 "저장하면 ○시간"을 미리 보여줍니다.
  (시작 · 끝 시간이 있는 일지만 계산 · 같은 날 겹치는 시간은 한 번만)
- **휴대폰 가로 보기**: 달력 위 **⟲ 가로로 보기** 버튼으로 화면을 가로로 돌려 7일을 한눈에 봅니다.
  앱은 휴대폰 자동 회전이 꺼져 있어도 돌아가고, 휴대폰 브라우저는 전체 화면으로 바뀝니다. (아이폰 사파리는 휴대폰을 직접 돌려 주세요)
- **상단 메뉴 한 줄**: 전체 · 돌봄 · 근무 · 일정 · 편집이 한 줄에 들어갑니다. 메뉴를 많이 늘리면 좌우로 밀어서 봅니다.
- **근무표와 동기화**: 해설사 근무표와 같은 데이터베이스를 읽습니다. 근무표 앱에서 근무를 바꾸면 이 캘린더에도 몇 초 안에 반영됩니다.
- **김태순 님 전용**: 이름 고르기 없이 근무표 앱과 같은 PIN 4자리로 로그인하고, 김태순 님의 근무만 가져옵니다.
  (명단에서 찾는 이름은 `VITE_OWNER_NAME`, 화면에 보이는 이름은 `VITE_DISPLAY_NAME` · 기본 "권희")
- **PC는 웹, 휴대폰은 안드로이드 앱(APK)**: 기록이 한 곳(Supabase)에 있어 둘을 함께 써도 같은 내용이 보입니다.
- **저장은 Supabase**: 돌봄 일지 · 일정 · 메뉴는 해설사 근무표와 **같은 Supabase 데이터베이스**의 전용 표에 저장됩니다.
  저장 · 불러오기가 0.5초 안팎으로 빠릅니다. (처음에는 구글시트에 저장했지만, 요청마다 3~6초씩 걸려 옮겼습니다)
- **김태순 님만 열람**: 행 수준 보안으로 본인 계정만 읽고 쓸 수 있습니다. 근무표의 다른 해설사는 볼 수 없습니다.
- **백업**: 설정 → **백업 · CSV 내려받기**로 모든 기록을 파일로 받아 둘 수 있습니다 (엑셀 · 구글시트에서 열림).
- **휴대폰 ↔ PC 반영**: 다른 기기에서 쓴 일지는 몇 초 안에 나타납니다 (실시간 알림 · 창으로 돌아올 때 · 1분마다).

## 1. Supabase 표 만들기 (한 번만)

> 표를 만들기 전에도 앱은 열리고 근무는 보입니다. "저장할 표가 아직 없습니다" 안내만 뜹니다.

1. 해설사 근무표가 쓰는 **같은 Supabase 프로젝트**의 대시보드를 엽니다. (김태순 님 계정)
2. 왼쪽 `SQL Editor` 를 열고 **[supabase/care_journal.sql](supabase/care_journal.sql)** 의 내용을 전부 붙여넣고 `Run`.
   (여러 번 실행해도 안전합니다)
3. 앱 `설정` 을 열면 "Supabase 에 저장됨 · 일지 0건" 이 나오면 끝입니다.

만들어지는 표

| 표 | 들어 있는 것 |
|---|---|
| **care_logs** | 돌봄 일지 — 날짜 · 시작 · 끝 · 대상·장소 · 한 일 · 특이사항 · 작성/수정 시각 |
| **care_events** | 한 줄 일정 — 날짜 · 시간 · 메뉴 · 내용 |
| **care_menus** | 상단 보기 메뉴 — 이름 · 색 |
| **care_settings** | AI 연결 키 |

- 모든 줄에 `owner_id`(근무표 명단의 id)가 붙고, 본인 것만 읽고 쓸 수 있게 보안 규칙이 걸립니다.
- `.env` 는 근무표 앱과 같은 값을 그대로 씁니다. 따로 넣을 값이 없습니다.

### 예전 구글시트에 기록이 있다면
앱 `설정 → 예전 구글시트의 기록 가져오기 ▸` 에 예전 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)를 넣고
**가져오기**를 누르면 일지 · 일정 · 메뉴를 한 번에 복사합니다. 여러 번 눌러도 같은 기록이 겹치지 않습니다.
(예전 스크립트 [google-apps-script/Code.gs](google-apps-script/Code.gs) 는 이 가져오기용으로만 남겨 두었습니다)

## 1-5. 말로 일지 채우기 · AI 연결 (AI 는 나중에 해도 됩니다)

일지 쓰기 화면의 **「한 일」 칸**에 휴대폰 **키보드의 마이크(🎤)** 로 받아쓴 뒤 **✦ AI 로 정리** 를 누릅니다.

| 순서 | 하는 일 |
|---|---|
| 1 | 「한 일」 칸을 누르고 키보드의 마이크(🎤)를 누른 뒤, 한 일 · 시간 · 대상 · 특이사항을 편하게 말합니다 |
| 2 | 「한 일」 아래 **✦ AI 로 정리** → AI(Claude)가 시작 · 끝 · 대상 · 한 일 · 특이사항 칸으로 나눠 넣습니다 |
| 3 | 더할 내용이 있으면 「한 일」에 이어서 받아쓰고 **AI 로 정리** 를 다시 누릅니다 → 기존 내용은 살리고 새 글만 덧붙입니다 ("시작은 9시가 아니라 10시"처럼 고치기도 됨) |
| 4 | 확인하고 **저장** (저장 버튼을 눌러야 저장됩니다) |

| 버튼 | 하는 일 |
|---|---|
| **✦ AI 로 정리** | 「한 일」의 글을 칸별로 나누기 (AI 연결 후에만 보임) |
| **초기화** | 날짜만 남기고 칸을 비움 |
| **↶ 되돌리기** | 방금 AI 정리 · 초기화를 취소 (직접 글자를 고치면 사라짐) |

- 말 → 글자는 휴대폰 키보드의 음성 입력이 맡습니다 (삼성 키보드 · Gboard 모두 됨). 브라우저 자체 음성 인식은
  휴대폰에서 말이 잠깐 끊길 때마다 멈추고 그 틈의 말이 새서 쓰지 않습니다. PC 는 윈도우 음성 입력(Win + H)으로 받아쓸 수 있습니다.
- AI 연결 전에는 「한 일」에 받아쓴 글이 그대로 남고, 시간 · 대상 · 특이사항은 직접 적습니다.

### AI 연결하기 (김태순 님 계정 · 한 번만)
1. https://console.anthropic.com 가입 → **Billing** 에서 크레딧 충전 → **Limits** 에서 월 사용 한도 걸기
2. **API Keys → Create Key** 로 키(`sk-ant-…`)를 만들고 복사
3. 앱(PC 또는 휴대폰) **설정 → AI 연결** 칸에 붙여넣고 **저장하고 AI 연결**
   → "AI 연결됨 · 키 sk-ant-…abcd" 가 나오면 끝입니다. PC · 휴대폰 모두 바로 AI 로 정리됩니다.

- 키는 Supabase 의 **본인 설정(care_settings)** 에만 저장되고, 기기 · GitHub 에는 남지 않습니다. 본인 계정만 읽을 수 있습니다.
- 저장할 때 앱이 Anthropic 에 키가 맞는지 확인합니다 (요금 없음). 크레딧이 없으면 AI 로 정리를 할 때 안내가 나옵니다.
- 정리 요청은 앱에서 Anthropic 으로 바로 보냅니다 (중간 서버 없음). 모델이 답하는 시간(보통 5~15초)만 걸립니다.
- **키 바꾸기 · 연결 끊기**도 같은 설정 화면에서 합니다.

### 비용 · 개인정보
- 한 번 정리에 대략 **10원 안팎** (Claude Sonnet 5, 말 길이에 따라 다름). Anthropic 콘솔 **Usage** 에서 확인합니다.
- AI 를 연결하면 받아쓴 내용이 정리를 위해 Anthropic 으로 보내집니다. API 로 보낸 내용은 AI 학습에 쓰이지 않습니다.
  어르신 성함 대신 "○○○ 어르신"처럼 말해도 됩니다.
- 체험 화면(`?demo`)에서는 AI 를 연결할 수 없습니다.

## 2. 내 컴퓨터에서 실행

```bash
npm install
npm run dev
```

`.env` 에는 해설사 근무표 폴더의 `.env` 와 **같은 값**이 들어 있어야 합니다. (`.env.example` 참고)
특히 `VITE_PIN_PEPPER` 와 `VITE_LOGIN_EMAIL_DOMAIN` 이 다르면 같은 PIN 으로 로그인되지 않습니다.

## 3. 인터넷에 올리기 (Vercel)

GitHub · Vercel 은 **김태순 님 계정**이 소유하고, 작업자는 GitHub 저장소 **협업자(Collaborator)** 로 고칩니다.

1. 김태순 님 GitHub 에 **공개(Public) 저장소**를 만들고 이 폴더를 올립니다.
   - 공개여도 되는 이유: 올라가는 것은 화면 코드뿐이고, 돌봄 기록은 Supabase 에 있습니다.
     `.env` · `release-key/` · 빌드 결과물은 `.gitignore` 로 막혀 있습니다.
   - **비공개로 하면 안 되는 이유**: Vercel 무료(Hobby) 요금제는 비공개 저장소에서
     소유자가 아닌 사람이 올린 커밋의 배포를 막습니다. (공개 저장소는 협업 무료)
2. 저장소 `Settings → Collaborators → Add people` 로 작업자 GitHub 계정을 초대합니다.
   (개인 계정 저장소는 권한을 고르는 칸이 없고, 초대받은 사람은 자동으로 수정 · push 할 수 있습니다. 작업자가 메일에서 **수락**해야 합니다)
3. 김태순 님 Vercel → `Add New… → Project` → 그 저장소 선택
4. `Environment Variables` 에 `.env` 의 값을 그대로 넣고 `Deploy`
   (`VITE_SUPABASE_URL` · `VITE_SUPABASE_ANON_KEY` · `VITE_LOGIN_EMAIL_DOMAIN` · `VITE_PIN_PEPPER` · `VITE_OWNER_NAME` · `VITE_SCHEDULE_URL`)

이후 작업자가 `main` 에 push 하면 Vercel 이 자동으로 다시 배포합니다.

> Supabase 의 표를 고치는 SQL(`supabase/*.sql`)은 김태순 님 계정의 대시보드에서 실행합니다.

## 4. 쓰는 법

| 하고 싶은 것 | 어떻게 |
|---|---|
| 오늘 일지 쓰기 | 위쪽 **＋ 오늘 일지 쓰기** |
| 말로 일지 쓰기 | 「한 일」 칸에 키보드의 마이크(🎤)로 받아쓰기 → **✦ AI 로 정리** (1-5 참고) |
| 90시간까지 남은 시간 | 캘린더 바로 위 **○월 돌봄 · 90시간까지** (시작 · 끝 시간을 넣어야 계산됩니다) |
| 휴대폰에서 7일 한눈에 | 달력 위 **⟲ 가로로 보기** · 돌아올 때 **⟲ 세로로 보기** |
| 오늘 일정 추가 | 위쪽 **＋ 일정** → 시간 · 메뉴 · 한 줄 내용 |
| 다른 날 쓰기 · 보기 | 캘린더에서 그 날짜를 누름 → **＋ 이 날 일정 추가** / **＋ 이 날 일지 쓰기** |
| 고치기 · 지우기 | 날짜를 누름 → 카드의 **수정** / **삭제** |
| 보고 싶은 것만 보기 | 위쪽 메뉴를 눌러 켜고 끄기 (여러 개 가능) · **전체**는 모두 켜기 |
| 메뉴 늘리기 · 색 바꾸기 | 위쪽 **✎ 메뉴 편집** |
| 긴 내용 끝까지 읽기 | 캘린더 칸에 전부 나오고, 아래 **○월 기록 모아보기**를 누르면 날짜순으로 펼쳐집니다 (기본은 접힘 · 펼친 기기는 다음에도 펼친 채로) |

**캘린더 표시** (색은 메뉴 편집에서 바꿀 수 있습니다)
- 근무 = 근무지 (점선 = 근무표에서 바뀐 근무, 안내 메모도 함께)
- 일정 = `● 시간 한 줄 내용` (길면 … 으로 줄임, 점 색 = 메뉴 색)
- 돌봄 일지 = 시간 · 대상 · 한 일 · 특이사항 전체 (왼쪽 선이 주홍색 = 특이사항 있음)
- 빨간 날짜 + 이름 = 공휴일 · 주홍 동그라미 = 오늘

**공휴일 표**는 [src/lib/holidays.ts](src/lib/holidays.ts)에 2025~2027년이 들어 있습니다.
설·추석처럼 해마다 날짜가 바뀌므로, 2028년이 되기 전에 다음 해를 덧붙여 주세요.

## 5. 안드로이드 앱 (APK)

### 만들기
```bash
npm run build
npx cap sync android
cd android
gradlew.bat assembleRelease
```
결과물: **`apk/돌봄근무일지.apk`** (빌드가 끝나면 자동으로 복사됩니다)

> 빌드 중간 파일은 OneDrive 밖(`사용자 폴더\.dolbom-android-build`)에 만듭니다.
> 프로젝트가 OneDrive 안에 있어 동기화가 파일을 붙잡으면 빌드가 실패하기 때문입니다.

### 휴대폰에 설치
1. APK 파일을 카카오톡(나에게 보내기) · USB · 구글 드라이브 등으로 휴대폰에 옮깁니다.
2. 파일을 누르면 "출처를 알 수 없는 앱" 허용을 묻습니다 → 허용 → 설치
3. 처음 한 번 PIN 으로 로그인하면 계속 유지됩니다.

### 웹페이지를 고치면 앱도 다시 설치해야 하나?
- **지금 방식 (화면을 앱 안에 담음)** — 네. 위 "만들기"로 새 APK 를 만들어 **덮어 설치**합니다.
  기록은 Supabase 에 있으므로 사라지지 않습니다. 덮어 설치할 때마다 `android/app/build.gradle` 의 `versionCode` 를 1씩 올려주세요.
- **웹 주소 연결 방식 (권장, Vercel 주소가 생긴 뒤)** — `capacitor.config.ts` 에 아래를 넣고 APK 를 **한 번만** 다시 만들면,
  그 뒤로는 웹만 고쳐도 앱에 자동 반영됩니다.
  ```ts
  server: { url: 'https://(Vercel 주소)', cleartext: false },
  ```

### ⚠️ 앱 서명키 — 반드시 백업
`release-key/` 폴더(`dolbom-release.jks`, `keystore.properties`)는 APK 서명키입니다.
**잃어버리면 새 APK 를 기존 앱 위에 덮어 설치할 수 없습니다** (앱을 지우고 새로 설치해야 함).
저장소(GitHub)에는 올라가지 않도록 막아두었으니, 별도로 안전한 곳에 복사해 두세요.

## 6. 폴더 구조

```
supabase/care_journal.sql     돌봄 일지 · 일정 · 메뉴 · AI 키 표와 보안 규칙 (Supabase SQL Editor 에서 한 번 실행)
```
